# TRACEABILITY: every requirement ID to its specification, module, code and tests

What this is: one table tracing each requirement ID (FR-COM-01 to NFR-USE-03) to its spec, module, code, tests and status.
How to read it: one row per requirement. The requirement text itself was not available (no `doc_inputs/`). Each summary comes either from Andrew's brief (marked [SPEC]) or from the ID's category alone (marked [INFERRED]), so check every [INFERRED] summary against D1.
"brief" = Andrew's `HMS_behaviour_modules_brief.md` (outside the repo; it summarizes D1 and teammates' specs). Module IDs are those in CODE_MAP.md.
Tags: [CODE] read in the named file; [SPEC] stated in the brief; [INFERRED] my reading. Status = Implemented, Partial, Not implemented, Not testable, or Unknown when the requirement's meaning could not be found.
Test files are in `Subgroup_B/tests/`; only behaviour-hiding code (B-modules) has tests in the repo. Counts as of 2026-11-06: 215 tests pass.
